01 / order-of-operations

Execution order

MySQL doesn't run a query top to bottom. This is the actual logical order it evaluates clauses in — it's why you can't use a SELECT alias in a WHERE clause, but you can in ORDER BY.

1
FROM / JOIN
Build the working set — pick base table(s), resolve joins
2
ON
Filter rows while joining, before tables are combined into one set
3
WHERE
Filter individual rows — no aggregates or SELECT aliases allowed here
4
GROUP BY
Collapse rows into groups based on column values
5
HAVING
Filter groups — this is where aggregate conditions belong
6
SELECT
Compute the output columns and expressions
7
DISTINCT
Remove duplicate rows from the result set
8
ORDER BY
Sort the final result — aliases from SELECT are valid here
9
LIMIT / OFFSET
Trim to the requested number of rows
02 / ddl-dml

Basics

The core statements for defining and changing data.

CREATE TABLE

Define a table and its constraints

CREATE TABLE users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  email VARCHAR(100) UNIQUE,
  created_at DATETIME DEFAULT NOW()
);

INSERT

Add new rows

INSERT INTO users (name, email)
VALUES ('Shams', 'shams@example.com');

UPDATE

Modify existing rows — always pair with WHERE

UPDATE users
SET email = 'new@example.com'
WHERE id = 1;

DELETE

Remove rows — omitting WHERE deletes everything

DELETE FROM users
WHERE id = 1;

ALTER TABLE

Change structure after creation

ALTER TABLE users
ADD COLUMN age INT;

Constraints

Common column-level rules

PRIMARY KEY   -- unique row identifier
FOREIGN KEY   -- references another table
NOT NULL      -- value required
UNIQUE        -- no duplicate values
DEFAULT val   -- fallback value
03 / select-anatomy

Query syntax

Anatomy of a SELECT statement, and the filtering operators you'll use inside WHERE.

Full SELECT shape

SELECT [DISTINCT] col1, col2, ...
FROM table_name
[JOIN other_table ON condition]
[WHERE condition]
[GROUP BY col1, col2, ...]
[HAVING aggregate_condition]
[ORDER BY col1 [ASC|DESC]]
[LIMIT n [OFFSET m]];

WHERE operators

=  !=  <>  <  >  <=  >=

WHERE age BETWEEN 18 AND 30
WHERE country IN ('CA','US')
WHERE name LIKE 'S%'
WHERE email IS NOT NULL

Aliasing & sorting

SELECT name AS full_name
FROM users AS u
ORDER BY full_name DESC
LIMIT 10 OFFSET 20;
04 / combining-tables

Joins

How two tables (A, B) combine. Shaded region is what's returned.

INNER JOIN

Only matching rows in both tables

SELECT *
FROM orders o
INNER JOIN users u
  ON o.user_id = u.id;

LEFT JOIN

All of A, matched rows from B (NULL if none)

SELECT *
FROM users u
LEFT JOIN orders o
  ON u.id = o.user_id;

RIGHT JOIN

All of B, matched rows from A (NULL if none)

SELECT *
FROM users u
RIGHT JOIN orders o
  ON u.id = o.user_id;

FULL JOIN

MySQL has no FULL JOIN — union of LEFT + RIGHT

SELECT * FROM a
LEFT JOIN b ON a.id=b.id
UNION
SELECT * FROM a
RIGHT JOIN b ON a.id=b.id;

CROSS JOIN

Every row in A paired with every row in B

SELECT *
FROM sizes
CROSS JOIN colors;

SELF JOIN

A table joined to itself, via aliases

SELECT e.name, m.name AS manager
FROM employees e
JOIN employees m
  ON e.manager_id = m.id;
05 / group-and-summarize

Aggregation functions

Functions that collapse many rows into one value, typically used with GROUP BY.

FunctionReturns
COUNT(col)Number of non-NULL rows. COUNT(*) counts all rows including NULLs
SUM(col)Total of a numeric column
AVG(col)Mean of a numeric column
MIN(col)Smallest value
MAX(col)Largest value
GROUP_CONCAT(col)Concatenates group values into one string
COUNT(DISTINCT col)Number of unique non-NULL values

GROUP BY + HAVING

Group rows, then filter the groups

SELECT user_id, COUNT(*) AS order_count
FROM orders
GROUP BY user_id
HAVING COUNT(*) > 5;

GROUP_CONCAT

Roll up related rows into one string

SELECT user_id,
  GROUP_CONCAT(product SEPARATOR ', ') AS items
FROM orders
GROUP BY user_id;

ROLLUP

Adds subtotal / grand-total rows to a group

SELECT region, SUM(sales)
FROM orders
GROUP BY region WITH ROLLUP;

Mixing aggregate + non-aggregate

Every non-aggregated SELECT column must appear in GROUP BY

SELECT department, AVG(salary)
FROM employees
GROUP BY department;
06 / per-row-context

Window functions

Unlike GROUP BY, these compute a value per row while keeping every row in the output — using OVER() to define the "window" of related rows.

ROW_NUMBER()

Unique sequential number per partition

SELECT name, department,
  ROW_NUMBER() OVER (
    PARTITION BY department
    ORDER BY salary DESC
  ) AS rank_in_dept
FROM employees;

RANK() / DENSE_RANK()

Like ROW_NUMBER, but ties share a rank

SELECT name, score,
  RANK() OVER (ORDER BY score DESC) AS pos
FROM results;

Running total

Aggregate functions also work as window functions

SELECT order_date, amount,
  SUM(amount) OVER (
    ORDER BY order_date
  ) AS running_total
FROM orders;

LAG() / LEAD()

Look at the previous / next row's value

SELECT order_date, amount,
  LAG(amount) OVER (ORDER BY order_date) AS prev
FROM orders;
